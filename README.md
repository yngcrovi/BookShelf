## Общая архитектура 
### Авторизация и аунтификация
Осуществляется с помощью api (ссылка), нужно ввести логин и пароль от пользовательского КИС. После успешного входа, создаётся access и refresh токен:
- Access хранится в cookie браузера пользователя
- Refresh в:
  1. localstorage
  2. redis
  3. БД
     
Переменные, которые отвечают за формирование токенов, указывается в файле .env(ссылка на файл): 
  1. **ACCESS_TOKEN_EXP_SECOND** - время жизни access токена
  2. **REFRESH_TOKEN_EXP_SECOND** - время жизни refresh токена
  3. **TOKEN_ALGORITHM** - алгоритом шифрования
  4. **SECRET_KEY** - секретный ключ

### Вызов пациентов
(Разбить на 2 пункта, экран вызова и экран приглашения и их описывать отдельно)
(Также описать какие данные написаны на кнопке для разных страниц)
Есть 2 основных экрана - для врача(вызов)(мб ссылка и фото) и для пациентов(приглашение)(мб ссылка и фото). Пациенты разбиты на 2 группы: основное и дополнительное время. На экране приглашения, кнопки для пациентов, записанных на основное время выделены зелёным цветом(указать цвет), а на дополнительное жёлтым(указать цвет). На странице вызова пациенты разделены не по цвету, а по столбцам с соответсвующими заголовками.  После того, как врач вызывает пациента, кнопка становится серого цвета(указать цвет). После того, как пациента вызвали, на экране приглашения появится модальное окно с информацией о пациенте(фото).

По истечению время жизни access токена, для его обновления потребуется refresh токен. Если время жизни refresh токена истечёт, то пользователь должен будет заново войти в своей аккаунт.
